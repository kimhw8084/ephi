# B. Actual current-state code audit

## Method and scope

Inventory was generated by parsing the extracted Python source, recording file hashes and symbol locations. The portable suite was executed. Representative runtime, company composition, health/fusion/episode, metrology, exposure, advisory/workflow, history/RCA, value and qualification boundaries were inspected. Four targeted behavioral probes used the shipped synthetic fixture only. This is a code/design audit, not a formal proof of every algorithm, a security penetration test, or real-fab validation.

`evidence/source_inventory.json` contains the complete Python inventory. `evidence/audit_environment.json` identifies the interpreter/libraries and API routes. References identify this exact ZIP, not an unspecified GitHub main. Unprefixed EPHI module paths are abbreviated relative to `src/ephi/`; `company_port/` and `tests/` paths are relative to the extracted root. NiceGUI Base references are explicitly identified as belonging to the separate pinned repository.

## Boundary evidence

`tests/invariants/` checks domain independence, advisory not importing scientific implementations, economics downstream of health, company schema isolation, operations not recomputing science, and qualification control consuming evidence rather than running science. These are valuable checks, but mostly import/text invariants. They do not prove runtime absence of look-ahead, correct confidence calibration, or complete scientific correctness. Add behavior/property tests, not just more string prohibitions.

## NiceGUI Base evidence and corrected interpretation

Pinned `AGENTS.md` and `source/nicegui_base/ai/construction_manifest.json` govern application construction. They require public imports, registered patterns, DataSource pushdown, shared analysis/selection/workspace state, framework tokens, thin callbacks and explicit target evidence. `source/nicegui_base/__init__.py` exports reusable attention/data/engineering/timeline/evidence/state primitives. `examples/nicegui_base/golden_analysis_workspace.py` uses `ApplicationRuntime`, a workspace, data session and registered panels.

The repository's README also describes Project OS/product work. Do not treat every root demo/workspace as stable installed framework API. The EPHI integration authority is the pinned installed framework and its catalog/golden contracts. Template documentation explicitly leaves missing target/browser/human evidence pending; this review does not upgrade it.

## Audit conclusions

Preserve the scientific architecture, **not every current implementation behavior**. Fixing F04/F05 is required by the mission's own invariants and is not a license for a broad rewrite. Keep reference and production responsibilities distinct. Full source/target/browser qualification, company data validation and measured ROI remain open gates.
